# Как назначать сотрудников на заказы

## 1. Подключите базу

1. Создайте проект Supabase.
2. Для локального запуска укажите Project URL и публичный anon key в `config.js`. При сборке Render задайте эти же значения как `SUPABASE_URL` и `SUPABASE_ANON_KEY` в переменных окружения Static Site. Service role key в сайт добавлять нельзя.
3. В Supabase откройте **SQL Editor**, вставьте весь файл `supabase/schema.sql` и выполните его.
4. Создайте аккаунт владельца через страницу `/team.html`.
5. В Supabase откройте **Authentication → Users**, скопируйте UUID аккаунта владельца и выполните в SQL Editor:

   ```sql
   update public.profiles set role = 'creator' where id = 'UUID_АККАУНТА_ВЛАДЕЛЬЦА';
   ```

   Повторно запускать основную схему после этого не нужно. Триггер регистрации сохраняет роль существующего пользователя.

## 2. Добавьте сотрудника

1. Попросите сотрудника открыть `/team.html` и выбрать **«Создать аккаунт клиента»**.
2. После регистрации сотрудник должен подтвердить email, если Supabase запросил подтверждение, и войти.
3. Владелец открывает `/team.html`, блок **«Сотрудники»**, и нажимает **«Сделать сотрудником»** напротив аккаунта.
4. Попросите сотрудника обновить `/team.html` или выйти и войти снова. Появится список его назначенных заказов.

## 3. Назначьте заказ

1. Клиент входит в `/team.html`, описывает заказ и нажимает **«Отправить запрос»**.
2. Владелец или менеджер входит на ту же страницу и видит **«Управление заказами»**.
3. В карточке нужного заказа выберите сотрудника в поле **«Исполнитель»** и нажмите **«Сохранить назначение»**.
4. Сотрудник увидит заказ в списке **«Мои назначенные заказы»** и сможет менять его статус.
5. Клиент видит актуальный статус в разделе **«Мои заказы»**.

Снять назначение можно, выбрав **«Не назначен»** и сохранив изменение. Назначать исполнителей могут только роли `manager` и `creator`; сотрудник может читать только закреплённые за ним заказы и менять их статус через защищённую функцию базы.

## Роли

- `customer` — создавать заявки и видеть свои заказы.
- `employee` — видеть назначенные ему заказы и обновлять статусы.
- `manager` — видеть все заказы и назначать сотрудников.
- `creator` — владелец: управление заказами и каталогом.

Роль `manager` владельцу следует выдавать вручную только доверенным руководителям. Для начала используйте проверенный процесс назначения через SQL Editor.

> Страница заказов создаёт заявки без оплаты и доставки. Она подходит для приёма и распределения запросов; платежи и почтовые этикетки в неё не включены.

## Публикация на Render

1. Отправьте файлы проекта в GitHub. В репозитории должны быть `render.yaml`, `package.json`, `scripts/build-site.mjs`, `team.html` и `src/team.js`. Не загружайте `config.js`: Render сформирует его при сборке.
2. В Render создайте **New → Blueprint** и выберите репозиторий и ветку `main`. Render прочитает `render.yaml`; тип сайта — Static Site, команда сборки — `npm run build`, папка публикации — `dist`.
3. Для уже существующего Blueprint откройте Static Site → **Environment** и добавьте `SUPABASE_URL` со значением `https://<project-ref>.supabase.co` и `SUPABASE_ANON_KEY` со значением публичного anon key из Supabase **Project Settings → API Keys**. Сохраните изменения и нажмите **Manual Deploy → Deploy latest commit**.
4. Когда статус станет **Live**, откройте URL сайта и проверьте главную страницу и `/team.html`.

Если Blueprint sync показывает ошибку, нажмите **View details** у неудачной синхронизации. Пришлите сообщение целиком — это отдельная ошибка синхронизации конфигурации, её причина отображается в деталях.
