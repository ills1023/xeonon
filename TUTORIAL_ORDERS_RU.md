# Как назначать сотрудников на заказы

## 1. Подключите базу

1. Создайте проект Supabase.
2. Для локального запуска укажите Project URL и публичный anon key в `config.js`. При сборке Render задайте эти же значения как `SUPABASE_URL` и `SUPABASE_ANON_KEY` в переменных окружения Static Site. Service role key в сайт добавлять нельзя.
3. В Supabase откройте **SQL Editor**, вставьте весь файл `supabase/schema.sql` и выполните его. Если проект Supabase уже создан для сайта, повторно выполните обновлённую схему: она использует `IF NOT EXISTS` и заменяет политики/функции без удаления таблиц и заказов.
4. Создайте аккаунт владельца через страницу `/team.html`.
5. В Supabase откройте **Authentication → Users**, скопируйте UUID аккаунта владельца и выполните в SQL Editor:

   ```sql
   update public.profiles set role = 'creator' where id = 'UUID_АККАУНТА_ВЛАДЕЛЬЦА';
   ```

   Повторно запускать основную схему после этого не нужно. Триггер регистрации сохраняет роль существующего пользователя.

После этого выйдите из `/team.html` и войдите снова. У владельца появятся блоки управления командой и **«Редактор каталога»**.

## Редактор главной страницы

1. Откройте главную страницу сайта, нажмите **«Войти»** и войдите в аккаунт с ролью `creator`.
2. В окне аккаунта появится кнопка **«Редактор главной»**. Покупатели и обычные сотрудники эту кнопку не видят.
3. Меняйте тексты на русском, немецком и английском, цвет акцента, порядок блоков и их видимость. Предпросмотр на главной обновляется сразу.
4. Нажмите **«Опубликовать изменения»**. Они сохранятся в Supabase и загрузятся у посетителей сайта. Для работы этой функции запустите обновлённый `supabase/schema.sql` в SQL Editor.

## Конструктор каталога

1. Откройте **«Редактор главной» → «Каталог»**.
2. Заполните обязательные поля со звёздочкой: slug, цену, вес, категорию, названия и описания на трёх языках. Под формой обновляется карточка предпросмотра; после загрузки STL она использует эту модель.
3. Нажмите **«Сохранить товар»**. Публикацию можно выключить, чтобы оставить товар черновиком.
4. Чтобы удалить прежние товары, нажмите **«Удалить все товары каталога»** и подтвердите действие. Оно удаляет записи из Supabase и не запускается при каждом обновлении сайта.

Сохраняйте товары на опубликованном сайте Render или через `npm run dev` по адресу `http://localhost:8787`. Открытие `index.html` как `file:///...` блокирует запись в Supabase.

## 2. Управляйте каталогом

1. Каталог изначально пустой. Добавляйте товары через **«Войти» → «Редактор главной» → «Каталог»**. Страница `/team.html` также оставляет доступ к управлению товарами.
2. Для нового товара заполните slug (латинские буквы и дефисы), названия и описания на трёх языках, категорию, цену, вес и размеры.
3. По желанию загрузите изображение и файл STL. Разрешены JPG, PNG, WEBP, SVG и STL размером до 50 МБ. Файлы попадают в публичный каталог Supabase Storage; приватные данные и ключ service role в браузер не передаются.
4. Нажмите **«Сохранить товар»**. Опубликованный товар появится в магазине и получит страницу товара. Существующую позицию можно менять или снимать с публикации.
5. Опубликованный товар появляется в каталоге после сохранения. Если все товары удалены или ещё не добавлены, покупатели увидят аккуратное сообщение, что каталог пуст.

## Расчёт и отправка индивидуального заказа

На странице индивидуального проекта выберите пластик (10 €/кг) или смолу (10 €/л), задайте расход ползунком и опишите изделие. Цена в калькуляторе — стоимость сырья плюс наценка 60%: полный килограмм пластика или литр смолы стоит 16 €. Это предварительная оценка без работы, электричества и доставки.

Чтобы заявка появилась у команды в `team.html`, клиент должен войти в аккаунт и нажать **«Отправить заказ в мастерскую»**. Кнопка скачивания только сохраняет текстовый файл. Прикреплённый STL загрузится в приватное хранилище; владелец, менеджер и назначенный сотрудник увидят ссылку в заказе. Заказы, ранее сохранённые только как файл, автоматически в базе не появятся.

В `team.html` тёмная тема переключается круглой кнопкой в шапке и использует сохранённую для сайта тему.

## 3. Добавьте сотрудника

1. Попросите сотрудника открыть `/team.html` и выбрать **«Создать аккаунт клиента»**.
2. После регистрации сотрудник должен подтвердить email, если Supabase запросил подтверждение, и войти.
3. Владелец открывает `/team.html`, блок **«Команда и роли»**, выбирает роль **«Сотрудник»** и нажимает **«Сохранить роль»**.
4. Попросите сотрудника обновить `/team.html` или выйти и войти снова. Появится список его назначенных заказов.

## 4. Назначьте заказ

1. Клиент входит в `/team.html`, описывает заказ и нажимает **«Отправить запрос»**.
2. Владелец или менеджер входит на ту же страницу и видит **«Управление заказами»**.
3. В карточке нужного заказа выберите сотрудника в поле **«Исполнитель»** и нажмите **«Сохранить назначение»**.
4. Сотрудник увидит заказ в списке **«Мои назначенные заказы»** и сможет менять его статус.
5. Клиент видит актуальный статус в разделе **«Мои заказы»**.

Снять назначение можно, выбрав **«Не назначен»** и сохранив изменение. Назначать исполнителей могут только роли `manager` и `creator`; сотрудник может читать только закреплённые за ним заказы и менять их статус через защищённую функцию базы.

## Роли

- `customer` — создавать заявки и видеть свои заказы.
- `employee` — видеть назначенные ему заказы и обновлять статусы.
- `manager` — видеть все заказы и назначать сотрудников. Владелец выдаёт эту роль в списке «Команда и роли»; давайте её только доверенному руководителю.
- `creator` — владелец: управление заказами и каталогом.

> Страница заказов создаёт заявки без оплаты и доставки. Она подходит для приёма и распределения запросов; платежи и почтовые этикетки в неё не включены.

## Публикация на Render

1. Убедитесь, что изменения отправлены в GitHub в репозиторий `ills1023/xeonon`, ветка `main`. Файл `config.js` не загружайте: Render сформирует публичную конфигурацию из переменных окружения.
2. В Render нажмите **New → Blueprint**, выберите `ills1023/xeonon` и ветку `main`. Render прочитает `render.yaml`; команда сборки — `npm run build`, папка публикации — `dist`.
3. В Render откройте созданный Static Site → **Environment** и укажите `SUPABASE_URL` (`https://<project-ref>.supabase.co`) и `SUPABASE_ANON_KEY` (публичный ключ из Supabase **Project Settings → API Keys**). Сохраните и запустите deploy.
4. В Supabase откройте **Authentication → URL Configuration**: добавьте URL сайта Render в **Site URL** и `https://<имя-сайта>.onrender.com/**` в **Redirect URLs**.
5. Дождитесь статуса **Live**, проверьте главную страницу и `/team.html`, затем зарегистрируйте тестового клиента и проверьте заявку. Создайте аккаунт владельца и назначьте ему роль `creator` описанным выше SQL.

Если Blueprint sync показывает ошибку, нажмите **View details** у неудачной синхронизации. Пришлите сообщение целиком — это отдельная ошибка синхронизации конфигурации, её причина отображается в деталях.
